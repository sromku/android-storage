? How this works

This page talks to the collector running on this computer. The phone streams every monitor's events to it over HTTP, and they're kept in a local SQLite database with no row limit — ideal for long capture runs.

Set the collector running (step 1), point the app at it (step 2), then watch the data land (step 3). Each monitor writes its own table:

APP-OPS sensitive access & denials INTENTS activity intents BROADCASTS received broadcasts NOTIFICATIONS posted notifications

1 Start the collector

From the repo root, run the collector. It creates the SQLite database if it doesn't exist yet (in tools/collector-data/, which is gitignored) — no setup needed.

python3 tools/collector.py

Or do the USB tunnel and collector in one go — it asks which device if several are connected:

./tools/collect.sh
Expected: it prints the web-tool URL and the app URL. Then open this page at http://localhost:8899.

2 Connect the app

In the app: Settings → External collector, turn it on and paste one of these URLs. Then hit Test connection in the app (or below).

WI-FI Same network
Phone and computer on the same Wi-Fi.
http://…:8899
USB adb tunnel
Use this if your Wi-Fi blocks device-to-device connections. The script sets up the tunnel and asks which device if several are connected.
./tools/adb-reverse.sh
http://127.0.0.1:8899
